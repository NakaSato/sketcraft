# CLAUDE.md — sketcraft-ui-egui

The egui + wgpu front end (layer L5): a thin shell over `sketcraft_engine::Session`. Panels read
engine state and act through commands (`SolveApp::run(id, params)` / `SolveApp::start(id)`).
Nothing here owns design data. Both apps (`apps/sketcraft`, `apps/sketcraft-web`) run the same
`SolveApp`. See the root CLAUDE.md, and AGENTS.md: most of its rules (persisted state, modals,
inspector tables, English UI text) apply to this crate.

## Commands

```sh
cargo test -p sketcraft-ui-egui --lib                    # unit tests (src/*_tests.rs, mod tests)
cargo test -p sketcraft-ui-egui --lib keymap             # one area by name filter
cargo test -p sketcraft-ui-egui --test scenarios         # every tests/scenarios/*.json
cargo test -p sketcraft-ui-egui --test scenarios sketch_line   # scenarios whose name matches
cargo test -p sketcraft-ui-egui --test ui_layout         # one integration test file
cargo check -p sketcraft-ui-egui --target wasm32-unknown-unknown
# Try a scenario file that is not in tests/scenarios:
SKETCRAFT_SCENARIO_FILE=x.json cargo test -p sketcraft-ui-egui --test scenarios adhoc -- --ignored --nocapture
```

- Scenario env vars: `SKETCRAFT_SCENARIO_SHOTS=<dir>` writes `{"shot"}` renders headless;
  `SKETCRAFT_SCENARIO_KEEP=1` keeps a scenario's temp folder.
- GPU tests skip when no adapter is found. Set `SKETCRAFT_REQUIRE_GPU=1` to make that a failure.
- Many `#[ignore]` tests write review images or time things (`SKETCRAFT_*_EVIDENCE`,
  `SKETCRAFT_BENCH_*`). Run them explicitly with `-- --ignored --nocapture`.
- Dev-dependencies turn on `sketcraft-engine/bundled-render-library` and `profile`.
- The whole crate is large (~280k lines). Prefer a filtered test run over the full suite.

## Layout

Entry points:
- `src/lib.rs`: `SolveApp` (state, `new`, `run`, `start`, `ui`), `Services` (host hooks: file
  pickers, show-in-folder, graphics path…), and the sorted `mod` list.
- `src/control.rs`: the control-channel methods (`engine.execute`, `ui.start`, `ui.click`,
  `ui.screenshot`, …). The apps provide the transport.
- `src/scenario.rs`: the headless `Harness` that runs scenario JSON steps; its module doc lists
  every step kind.

Shell and workspace:
- `src/toolbar.rs`: application bar, ribbon tabs and panels, shortcuts. `src/toolbar_custom.rs`:
  user toolbar customisation. `src/titlebar.rs`, `src/status_bar.rs`, `src/home.rs`.
- `src/workspace.rs`: ribbon structure as data (`TABS`, `SECTIONS`, `destination`). It includes the
  `SKETCHUP_TAB` ("SKETCHUP"), a tab of shortcuts to commands whose home is another tab.
- `src/viewport.rs` (+ `viewport_*.rs`): 3D viewport, picking, overlays. `src/gpu.rs`: the
  `egui_wgpu` paint callback glue; pipelines live in `crates/gpu`. `src/navigation.rs`: the one
  camera input handler (`navigation::handle`).
- `src/browser.rs` + `src/browser/`, `src/timeline.rs`, `src/timeline_left.rs`: left browser tree
  and feature timeline.
- `src/dialogs.rs` + `src/dialogs_*.rs`: command dialogs (forms that build command params).
- `src/tools.rs`, `src/sketch_tools.rs`, `src/sketch_*.rs`: interactive sketch tools (UI state only).
- `src/context_menu.rs`, `src/keymap.rs`, `src/command_help.rs` (`DOCUMENTED`, `help.<id>`).
- `src/render_workspace*.rs`, `src/render_ui/`: the Render workspace and its inspector.
- `src/agent_chat/`: the agent chat (ACP and API agents). `src/update.rs` + `src/update/`: update
  check. `src/documents.rs`: several open designs as tabs.
- Off-thread work: `src/save_job.rs`, `src/file_load.rs`, `src/control_job.rs`.

Shared building blocks:
- `src/ui_kit/`: containers, panels, sections (`layout.rs`), tables (`table.rs`), modals
  (`confirm.rs`, `container.rs`, `actions.rs`), disclosures, sliders, rows. Use these first.
- `src/theme.rs` (`Tokens`), `src/theme_files.rs`: colours and theme files.
- `src/prefs.rs` + `src/prefs/`: the serialized `Prefs` (`STORAGE_KEY = "sketcraft.prefs"`) and
  the `preference_settings!` table. `src/settings_profiles.rs`.
- `src/i18n.rs` (`tr`, `tr_label`, the language list), `src/bidi.rs`, `src/fonts.rs`.
- `src/icon_svg.rs`, `src/icons.rs`: icons from the SVG masters.

Tests:
- `tests/scenarios/*.json` (150 files): one test each, generated by `build.rs`.
- `tests/*.rs`: layout, render and preselection checks. Shared helpers in `tests/support/`;
  theme fixtures in `tests/fixtures/`. `examples/acp_test_agent.rs`: a scripted ACP agent.

`build.rs` stamps the git commit and build date, embeds themes from `assets/styles/ui/themes`,
merges `assets/locales/*.json` with `assets/locales/pending/*.json`, compiles icon data from
`assets/icons/ui/design`, and generates the scenario tests. A bad asset fails the build.

## Rules

- Act through commands (`app.run` / `app.start`); never change the design directly. New behaviour
  is a `CommandSpec` in `crates/engine/src/cmd/` first: `skills/sketcraft-commands/SKILL.md`.
- Depend on lower crates through `sketcraft_engine` re-exports (`sketcraft_engine::doc`, `geom`, …);
  the only workspace crates in `[dependencies]` are `sketcraft-engine`, `sketcraft-gpu` and
  `sketcraft-space-mouse`.
  `unsafe` is forbidden; the crate root denies `unwrap`/`expect`/`panic!`.
- UI containers: use `ui_kit::Container` / `Panel` / `Window` / `Confirm` / `Menu`. No raw
  `egui::Modal`/`egui::Window`/`CollapsingHeader`. `cargo xtask ui-containers` and
  `src/ui_kit_guard_tests.rs` enforce it. Modal button order and tables: AGENTS.md.
- Colours, sizes and fonts come from `theme::Tokens`. No literal colours in feature code.
- Camera input only through `navigation::handle`; `hand_rolled_camera_input_is_rejected` fails otherwise.
- Every option, tool choice and expandable section persists across restarts (AGENTS.md). Put
  settings in `Prefs`, with defaults for new fields; use `ui_kit` sections with stable ids.
  See `skills/sketcraft-preferences/SKILL.md`.
- Text: English only (AGENTS.md). New strings go in a new `assets/locales/pending/<slug>.json`, read
  with `i18n::tr("ui.id")`. Toolbar commands need `cmd.<id>` and `help.<id>` and an entry in
  `command_help::DOCUMENTED`. See `skills/sketcraft-ui-text/SKILL.md`.
- Do not block the window thread: long work runs beside it (`save_job.rs`, `file_load.rs`).
  See `skills/sketcraft-performance/SKILL.md`.
- Must build for wasm32. Guard native-only code with `cfg(not(target_arch = "wasm32"))` (e.g.
  `arboard`); use `web_time` for time.
- A UI bug fix gets a scenario JSON or a `*_tests.rs` case: `skills/sketcraft-tests/SKILL.md`,
  `skills/sketcraft-ui/SKILL.md`.

## Gotchas

- Prefs fall back to the legacy key `solvecraft.prefs` when `sketcraft.prefs` is missing.
- A scenario with a `{"pending": "why"}` step becomes an ignored test. Remove the step in the fix.
- `build.rs` reruns on scenario, locale and icon changes; a new scenario file needs no Rust edit.
- The apps write prefs each frame (rate-limited), not this crate: desktop `PrefsWriter::store`
  in `apps/sketcraft/src/main.rs`, web in `apps/sketcraft-web/src/main.rs`.
